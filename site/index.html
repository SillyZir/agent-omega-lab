Engineering demonstration

Autonomous AI repair system for open-source projects.

Agent Omega finds, localizes, fixes, and tests bugs in open-source projects. Its patches have been merged by maintainers of projects including Caddy, rclone, go-ethereum, and k3s. In one documented case, the complete repair-to-merge workflow ran without human intervention.

Judgment calls

Three design decisions

Fail closed on uncertainty

DecisionUnknown or incomplete results block shipment.

WhyA retry can hide a real failure, create duplicate actions, or turn an ambiguous outcome into a false success.

Trade-offSome recoverable jobs require manual investigation. Safety takes priority over throughput.

Give the second judge neutralized issue text

DecisionRemove attacker-controlled framing before the second review.

WhyIssue descriptions are untrusted input. The second judge evaluates the fix without being steered by instructions embedded in the report.

Trade-offNeutralization is deliberately greedy and can strip harmless context; if the two verdicts then diverge, the candidate goes to human review instead of shipping. A lost candidate is cheaper than a steered patch.

Keep the public demo recorded

DecisionReplay verified evidence rather than execute live model sessions on the public website.

WhyVisitors inspect the repair workflow without exposed credentials, untrusted code execution, or model charges.

Trade-offVisitors cannot submit new bugs to the public site. Real execution remains a controlled, local capability.

Long-form rationale: autonomy & authority in the showcase documentation.

Under the hood

Full technical details

Pipeline architecture
  • Localize — a read-only model session names the faulty files from the issue text alone (78.4% top-1 on 37 ground-truth issues; keyword baseline 10.8%).
  • Patch — a bounded session (file tools, no shell) edits the checkout; only the diff is kept.
  • Regression test — a fix-blind session writes a test that must FAIL on base and PASS on patch, twice, stably.
  • Judge ×2 — independent review passes; the second reads neutralized issue text so steering produces a divergence.
  • 16 release gates — budgets, capacity, policy, scope, lints, breaker; a gate that errors fails closed.

Numbers & limitations
  • Localization: 78.4% top-1 (29/37) and 89.2% top-3 (33/37) on 37 issues with merged human fixes; keyword baseline 10.8% (4/37).
  • Fixes: an LLM judge — not test execution — rated 45.9% of patches (17/37) equivalent to the merged human fix. Of 45 end-to-end validation runs against the projects' own test suites, 4 produced a test-verified fix, 9 demonstrably failed, and 32 were environmentally inconclusive.
  • Honest negatives: a Rust expansion closed NO-PROMOTE on pre-registered bars, twice; one PR withdrawn as a design finding.
  • The seeded demo bug is easier than production work; recorded output is recorded; live sessions vary.
  • A merged PR proves a change passed one repository's review — nothing more universal.
  • Reproduction tested on macOS/arm64 (go 1.25, python 3.14); Linux expected, unverified.
Security model & failure injection

Reasoning does not confer authority. Model and external text are untrusted inputs to a deterministic control plane. Six injected failures, six blocks (the demo's third tab, or make inject):

  • Plausible-but-wrong patch → tests catch it; tests_pass refuses.
  • Prompt-injection in the issue text → injection_lint refuses.
  • Diff touching CI config → content_lint refuses.
  • Oversized 40-file diff → size_caps refuses.
  • Tripped circuit breaker → breaker_armed refuses.
  • Missing state file → the gate errors and fails closed.
